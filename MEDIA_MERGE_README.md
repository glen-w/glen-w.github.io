# Media Page Merge - Project Notes

## Project Overview

This document contains project notes and technical details for merging the separate media page (`_pages/media.md`) into the library page (`_pages/library.md`) while maintaining the inline audio player functionality for media appearances.

## Current Structure Analysis

### Library Page (`_pages/library.md`)

- Uses Jekyll-Scholar plugin to render bibliography from `papers.bib`
- Includes search functionality via `bib_search.liquid`
- Renders academic publications using `bib.liquid` layout
- Configured in `_config.yml` under Jekyll Scholar section

### Media Page (`_pages/media.md`)

- Renders media entries from `_media/` directory
- Uses `media.liquid` include for rendering
- Media entries are processed as Jekyll posts with `inline: true`
- Audio players embedded via `audio.liquid` include

### Audio Functionality

- HTML5 `<audio>` tags with controls
- Audio files stored in `assets/audio/`
- Audio include supports cache busting, autoplay, loop, muted options

## Zotero Integration Notes

### Important: Bibliography Management

- **papers.bib is generated by Zotero** - do not edit directly
- All changes must be made in Zotero first, then exported
- Media entries should be added as new item types in Zotero
- Export format should maintain BibTeX compatibility

### Zotero Item Type Setup

For media appearances, consider creating custom item types or using existing ones:

- **Broadcast** - for radio/TV appearances
- **Interview** - for media interviews
- **Podcast** - for podcast appearances
- **Web Article** - for online media coverage

### Required Fields for Media Entries

When adding media items to Zotero, ensure these fields are populated:

- Title
- Author (Glen Wright)
- Date (year, month, day)
- Publication/Outlet
- URL (if applicable)
- Audio file reference
- Type classification

### Export Considerations

- Export from Zotero as BibTeX format
- Ensure custom fields are properly exported
- Test export with sample media entries before full migration
- Verify audio file paths are correctly referenced

## Technical Notes

### Jekyll-Scholar Configuration

Current configuration in `_config.yml`:

```yaml
scholar:
  source: /_bibliography/
  bibliography: papers.bib
  bibliography_template: bib
  query: "@*"
  group_by: year
  group_order: descending
```

### Audio Include Functionality

The `audio.liquid` include supports:

- `path`: Audio file path
- `controls`: Show/hide player controls
- `class`: CSS classes for styling
- `autoplay`: Auto-play audio
- `loop`: Loop audio playback
- `muted`: Start muted
- `cache_bust`: Cache busting for file updates

### File Path Considerations

- Audio files are stored in `assets/audio/`
- Paths in BibTeX should be relative to site root
- Consider using site.baseurl for proper URL generation
- Test file paths in both development and production environments
